1What is SQL?

SQL stands for Structured Query Language. It is the language we use to talk to a relational database. With SQL you can create tables, put data into them, change that data, and most importantly for an analyst, ask questions and get answers back.

People say it two ways: as letters, "S-Q-L", or as a word, "sequel". Both are correct.

You say what you want, not how to get it

Think about ordering food in a restaurant. You say "one paneer butter masala and two rotis". You do not tell the cook which pan to use or how long to stir. The kitchen works that out.

SQL works the same way. You describe the result you want, and the database works out the steps to get it. This style is called declarative. It is different from a language like Python, where you usually write every step yourself, like a recipe.

Example: a question written in SQL
SELECT first_name, city
FROM customers
WHERE country = 'India';

Read it out loud: "select the first name and city, from the customers table, where the country is India." That is almost plain English. You never told the database how to search the table. You only described what you want back.

One language, a few accents

SQL is a standard, but each database product adds a few small changes of its own. These versions are called dialects. Think of English in India, the UK and the US. The core language is the same, but some words differ ("lift" and "elevator", "colour" and "color").

What you wantMySQLSQL ServerPostgreSQL
First 5 rows onlyLIMIT 5TOP 5LIMIT 5
Today's dateCURDATE()GETDATE()CURRENT_DATE
Auto-numbered IDAUTO_INCREMENTIDENTITYSERIAL

About 95% of what you write is the same everywhere. In this series we use MySQL 8, and we point out the differences when they matter.

Two small habits before we go on. SQL keywords are not case-sensitive, so select and SELECT work the same. By habit, we write keywords in CAPITALS and our own names (tables, columns) in lowercase, which makes queries easier to read. And every SQL statement ends with a semicolon ;, the same way a sentence ends with a full stop.

2The five families of SQL commands

Every SQL command belongs to one of five families, based on the kind of job it does. Once you know the families, any new command you meet has a place to go.

To make them easy to remember, picture yourself running a shop.

DDLData Definition Language

Builds and changes the structure

In the shop: putting up the shelves and deciding what goes where. DDL creates tables, changes their columns, or removes them. It works on the container, not on what is inside.

CREATEALTERDROPTRUNCATE
DDL example (Day 3)
CREATE TABLE categories (
    category_id   INT PRIMARY KEY,
    category_name VARCHAR(50)
);
DMLData Manipulation Language

Adds, changes and removes the data

In the shop: putting products on the shelves, changing a price tag, taking an item off the shelf. DML works on the rows inside the tables.

INSERTUPDATEDELETE
DML examples (Day 4)
INSERT INTO categories (category_name) VALUES ('Books');

UPDATE products SET price = 649 WHERE product_id = 5;
DQLData Query Language

Reads the data and answers questions

In the shop: walking around and checking what is on the shelves. "Which products cost more than ₹1,000?" DQL has really one command, SELECT, but it is the one you will use most as an analyst. It never changes the data, so it is safe to try anything.

SELECT
DQL example (Days 5 to 9)
SELECT product_name, price
FROM products
WHERE price > 1000;
DCLData Control Language

Decides who is allowed to do what

In the shop: handing out keys. The manager gets a key to everything, while a new helper can only look. DCL gives and takes away permissions. As an analyst you will mostly use permissions someone else set up for you.

GRANTREVOKE
DCL example (Day 19)
GRANT SELECT ON online_store.* TO 'riya'@'localhost';

This lets the user riya read every table in online_store, but not change anything.

TCLTransaction Control Language

Saves or undoes a group of changes together

In the shop: when a customer buys 2 mice, two things must happen. The stock goes down by 2, and the sale gets recorded. If only one of them happens, your records are wrong. TCL lets you treat both steps as one unit: save both, or undo both. This is the ACID idea from Day 1 in action.

START TRANSACTIONCOMMITROLLBACKSAVEPOINT
TCL example (Day 4)
START TRANSACTION;
UPDATE products SET stock_quantity = stock_quantity - 2 WHERE product_id = 1;
INSERT INTO order_items (order_id, product_id, quantity, unit_price) VALUES (16, 1, 2, 799);
COMMIT;

3Data types: what each column is allowed to hold

Think of the containers in a kitchen. Milk goes in a bottle, rice goes in a jar, eggs go in a tray. You pick the container that fits what it holds.

Columns work the same way. When you create a table, every column gets a data type that says what kind of value it can hold. Picking the right type matters for three reasons:

  • It blocks wrong data. A price column with a number type will refuse the word "hello".
  • It lets you do the right maths. You can add numbers and subtract dates, but you can't add two names.
  • It saves space. A small type for small values keeps a big table lighter and faster.

Numbers

TypeWhat it holdsGood for
INTWhole numbers, up to about 2.1 billionIDs, quantity (3), stock (150)
BIGINTVery large whole numbersPage views, IDs in huge tables
DECIMAL(p, s)Exact numbers with a decimal pointMoney: price ₹1,499.00
FLOAT, DOUBLEApproximate decimal numbersScientific readings, sensor data

DECIMAL(10,2) means "up to 10 digits in total, and 2 of them after the decimal point". So the biggest value it can hold is 99,999,999.99. That is plenty for product prices.

Why money should never be FLOAT

FLOAT and DOUBLE store numbers in an approximate way to save space. Most of the time you won't notice. But try adding 0.1 and 0.2 as floating-point numbers (the e0 at the end tells MySQL to treat them that way):

SQL
SELECT 0.1e0 + 0.2e0;
Result
0.30000000000000004

That tiny error is fine for a temperature reading. It is not fine for a bank balance or a sales total, where it can add up over millions of rows. DECIMAL stores the number exactly, so the rule is simple: money always goes in DECIMAL.

Text

TypeWhat it holdsGood for
VARCHAR(n)Text up to n characters, uses only the space it needsNames, emails, cities
CHAR(n)Text of exactly n characters, always the same sizeFixed codes: country code 'IN'
TEXTLong textProduct descriptions, reviews

An easy way to remember the difference: CHAR is a box that always takes the same space on the shelf, even if it is half empty. VARCHAR is a cloth bag that only takes as much space as what is inside, up to a limit. Text values are always written inside single quotes, like 'Mumbai'.

Dates and times

TypeWhat it holdsExample
DATEA calendar date'2024-03-14'
DATETIMEA date and a time'2024-03-14 09:30:00'
TIMESTAMPA date and time, stored in UTC and shown in your time zoneWhen a row was last changed
TIMEA time of day'09:30:00'

Dates are always written as YYYY-MM-DD. Here is why. In India, 03/04/2024 means 3rd April. In the US, it means 4th March. 2024-04-03 can only mean one thing, and it also sorts in the right order.

True or false

BOOLEAN holds a yes or no value, like "is this account active?". In MySQL it is stored as a tiny number behind the scenes: TRUE is 1 and FALSE is 0.

4NULL: when a value is missing

Imagine a sign-up form where someone leaves the "city" box empty. The database still has to store something in that row. It stores a special marker called NULL, which means "no value here, we don't know it".

NULL is not zero, and it is not an empty piece of text. Each of these means something different:

Value in discountWhat it means
0We know the discount, and it is zero.
NULLWe don't know the discount. Nobody filled it in.
Value in middle_nameWhat it means
'' (empty text)We know the person has no middle name.
NULLWe don't know if they have one.

In our example database, one customer, Noah Brown, has NULL in the city column because he never gave his city. You will meet him again many times.

Going deeper: SQL's three answers

In everyday logic, a question has two answers: true or false. SQL has a third answer: unknown. Any comparison with NULL gives unknown, because there is no way to tell.

ComparisonAnswerWhy
5 = 5TRUEClearly equal
5 = 6FALSEClearly not equal
5 = NULLUNKNOWNWe don't know the second value
NULL = NULLUNKNOWNTwo unknown values may or may not match

A real-life version: if I don't know your phone number and someone asks "is it 98765 43210?", the honest answer is not yes or no. It is "I don't know".

This is why the first query below finds nobody, even though Noah's city really is missing. A filter only keeps rows where the answer is TRUE, and city = NULL is never TRUE. The second query uses IS NULL, the correct way to check for a missing value. You will learn WHERE properly on Day 5, so for now just look at the results.

SQL
SELECT first_name FROM customers WHERE city = NULL;   -- wrong way
Result
(no rows)
SQL
SELECT first_name FROM customers WHERE city IS NULL;  -- right way
Result
Noah

One more rule: maths with NULL gives NULL. If a price is 500 and the discount is NULL, then price - discount is NULL, not 500. It's like a bill where one item has no price: the total can't be known. Day 8 shows how to handle this with COALESCE.

5Your practice setup

From Day 3 you will start typing SQL, so you need a place to run it. There are two good paths. Pick the one that is easier for you today. You can switch later, since the SQL stays the same.

Path A: online, nothing to install

  • Open a website that runs MySQL in the browser, such as DB Fiddle or OneCompiler (search "MySQL online").
  • Choose MySQL 8 if the site asks for a version.
  • Paste SQL, press Run, see the result.
  • Best for: starting today, on any computer.
  • Downside: your tables may be wiped when you close the page.

Path B: install MySQL on your computer

  • Install MySQL Community Server 8 and MySQL Workbench (both free from the MySQL website).
  • On Mac you can use brew install mysql. On Ubuntu, sudo apt install mysql-server.
  • Open Workbench and connect to your local server.
  • Best for: real practice. Your data stays saved, just like at work.
  • Other free tools that also work: DBeaver, VS Code with a MySQL extension.

Whichever path you pick, run this as your very first SQL. It asks MySQL which version it is:

SQL
SELECT VERSION();
Result
8.0.36

Your number may be a little different. What matters is that it starts with 8, and ideally is 8.0.16 or newer. A few features in this series (like CHECK rules on Day 3 and window functions on Day 9) need MySQL 8.

Every grey code box in this series has a Copy button in its top corner. Click it, paste into your tool, and run.

6Meet our example database: online_store

Learning SQL on random examples is hard to remember. So for this whole series we follow one story.

Imagine you have just joined a small online shop as its first data analyst. The shop sells electronics, books, clothing, home and kitchen items, and sports gear. Most customers live in India, with a few from other countries. Your job over the coming days: build the shop's database (Day 3), fill it with data (Day 4), and then answer the owner's questions with SQL (Day 5 onwards).

Why does order_items keep its own price?

products already has a price, so why store unit_price again in order_items? Look at an old restaurant bill. It shows what you paid that day, even if the menu price has gone up since.

Prices change over time. If an order only pointed to products.price, last year's sales would suddenly look bigger every time a price went up. So each order line keeps a copy of the price on the day it was sold. This is not a normalization mistake: today's price and the price paid on 10 January are two different facts.

Notice the naming habits. Every table name is plural and lowercase (customers, not Customer). Every column uses snake_case: lowercase words joined with underscores (customer_id, not customerId). The same key also keeps the same name in every table, so customer_id in orders clearly points to customer_id in customers. Picking one style and never breaking it means nobody on a team has to guess what a column is called.

Three kinds of relationships

Tables can be linked in three ways. Interviewers ask about these a lot.

TypeEveryday exampleIn online_store
One-to-oneA person and their passport. One person has one passport, and one passport belongs to one person.Not used here. It would fit something like a customer_profiles table with extra details.
One-to-manyA mother and her children. A mother can have many children, but each child has one mother.One customer has many orders. One category has many products. One order has many order lines.
Many-to-manyStudents and courses. A student takes many courses, and a course has many students.Orders and products. One order has many products, and one product appears in many orders.

A database can't store a many-to-many link directly. It needs a table in the middle, called a bridge table (or junction table). In our shop, order_items is that bridge. Think of the lines on a shopping bill: each line connects one bill to one product, and that is exactly what a row in order_items does.

🎯 Interview corner

These questions come up often in data analyst and data scientist interviews. Try to answer each one out loud before you open the answer. Keep your answers short and add a small example.

Concept questions

Q1What is SQL? Is it a programming language?

SQL (Structured Query Language) is the standard language for working with relational databases: creating tables, adding and changing data, and asking questions. It is a declarative language: you describe the result you want, and the database decides how to get it. It is not a general-purpose language like Python, because you can't build a full app with SQL alone, but it is a language with its own rules.

Q2What are the different types of SQL commands? Give one example of each.

There are five families. DDL builds structure (CREATE TABLE). DML changes data (INSERT, UPDATE, DELETE). DQL reads data (SELECT). DCL controls permissions (GRANT, REVOKE). TCL controls transactions (COMMIT, ROLLBACK).

Q3Is SELECT part of DML or DQL?

It depends on the source, and saying so shows you know the topic well. Many textbooks and database vendors put SELECT under DML, because it works with data rather than structure. Others split it into its own family, DQL, because it only reads and never changes anything. A good answer: "Some sources call it DML, others DQL. I think of it as DQL because it only reads data."

Q4What is the difference between CHAR and VARCHAR?

CHAR(n) always stores exactly n characters. Shorter values are padded with spaces, so it always uses the same space. VARCHAR(n) stores only the characters you give it, up to n, plus a small length marker. Use CHAR for values that are always the same length, like a 2-letter country code. Use VARCHAR for things like names and emails.

Q5Why should you use DECIMAL instead of FLOAT for money?

FLOAT stores numbers approximately, so tiny rounding errors appear. For example, 0.1 + 0.2 as floats gives 0.30000000000000004. Over millions of transactions, these errors add up to wrong totals. DECIMAL stores the exact value, so money adds up correctly.

Q6What is NULL? How is it different from 0 or an empty string?

NULL means the value is missing or unknown. 0 is a real number, and '' is a real piece of text that happens to be empty. Example: a discount of 0 means "no discount", but a NULL discount means "we don't know the discount".

Q7Why does WHERE city = NULL return no rows?

Because any comparison with NULL gives UNKNOWN, not TRUE, and WHERE only keeps rows where the condition is TRUE. SQL uses three-valued logic: TRUE, FALSE and UNKNOWN. To find missing values you must use IS NULL (or IS NOT NULL for the opposite).

Q8What is the difference between DATETIME and TIMESTAMP in MySQL?

Both store a date and a time. DATETIME stores exactly what you give it and covers years 1000 to 9999. TIMESTAMP converts the value to UTC when saving and back to your time zone when reading, and covers only 1970 to 2038. Use TIMESTAMP for "when did this happen" on systems used across time zones. Use DATETIME for fixed dates like a scheduled delivery.

Q9What are the types of relationships between tables? How do you store a many-to-many relationship?

One-to-one (a person and a passport), one-to-many (a customer and their orders) and many-to-many (orders and products). A many-to-many link needs a bridge table that holds a foreign key to each side. In our shop, order_items links orders and products.

Q10What is an SQL dialect?

A dialect is the version of SQL used by one database product, like MySQL, PostgreSQL or SQL Server. The core is the same, but some details differ. Example: getting the first 5 rows is LIMIT 5 in MySQL and TOP 5 in SQL Server.

The trap here is phone numbers and PIN codes. They look like numbers, but they are labels. You'd never add two phone numbers. If you store a phone as INT, a leading 0 or a +91 disappears. The other trap is age: it changes every year, so it would go out of date. Store the date of birth and work out the age when you need it.

P2Which family does each statement belong to?
SQL
CREATE INDEX idx_order_date ON orders(order_date);
SELECT * FROM products;
UPDATE orders SET status = 'Completed' WHERE order_id = 5;
REVOKE SELECT ON online_store.* FROM 'riya'@'localhost';

TRUNCATE TABLE order_items;
DELETE FROM order_items WHERE order_item_id = 25;

In order: DDL, DQL, DML, DCL, TCL, DDL, DML.

The tricky one is TRUNCATE. It removes all the rows, so it feels like DML. But it works by resetting the whole table, so it counts as DDL. In MySQL it can't be undone with ROLLBACK, while DELETE can. You'll see both on Days 3 and 4.

P3A product costs 500 and its discount is NULL. What does price - discount return?

It returns NULL, not 500. Any maths with NULL gives NULL, because one part of the sum is unknown. If you want "no discount" to count as 0, you have to say so with COALESCE(discount, 0), which you will learn on Day 8.

Quick recap

  • SQL is the language for relational databases. You describe what you want, and the database works out how to get it.
  • Each database product has its own dialect, but the core is the same. We use MySQL 8.
  • Five families: DDL builds structure, DML changes rows, DQL reads data, DCL controls permissions, TCL saves or undoes groups of changes.
  • Every column has a data type. Use INT for whole numbers, DECIMAL for money, VARCHAR for text, DATE for dates.
  • NULL means missing or unknown. It is not 0 and not empty text. Comparing anything with NULL gives UNKNOWN, so use IS NULL.
  • Our example database, online_store, has five tables: customers, categories, products, orders and order_items.
  • Relationships are one-to-one, one-to-many or many-to-many. A many-to-many link needs a bridge table, like order_items.
